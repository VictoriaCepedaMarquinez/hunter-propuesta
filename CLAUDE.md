# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

A single-page React marketing site proposal for "Hunter Bar" (Drink & Food; Instagram @hunterbartandil), Paz 497 esquina Pinto, Tandil, Argentina. The visual identity copies Hunter's Instagram: black grunge background, "HUNTER" in heavy condensed white lettering with a black inline and a flamingo ("Hunting Bird") standing on the R, black-and-white tropical palm leaves with white line icons (their story highlights), photos with the HUNTER mark centered at the bottom (their posts), and pill labels (the client went red → yellow → flamingo pink for the accent). Hunter takes no reservations ("Sin reservas - Sólo orden de llegada") and opens every day from 19 hs; there is no phone/WhatsApp ordering, so the CTAs are "Ver la Carta" and Instagram; the address in the Ubicación section links to Google Maps (the navbar has no "Cómo llegar" button — the client asked to remove it). Brand data (name, address, hours, no-reservations policy, Instagram) lives in `src/constants/marca.js`. Built with Vite, React 19, and Tailwind CSS v4, deployed on Vercel. No router, no client-side tests beyond Playwright e2e — pages are still switched via component state, not URL routes. A read-only `GET /api/products` Vercel Function backed by Neon Postgres still exists, but nothing in the UI consumes it anymore (the admin panel and the featured-products grid were removed).

## Commands

- `npm run dev` — start Vite dev server with HMR
- `npm run build` — production build (outputs to `dist/`)
- `npm run lint` — run ESLint over the project
- `npm run preview` — preview the production build locally

## Architecture

**No routing library.** `App.jsx` holds a `pagina` string in `useState` and manually switches between `Home` and `AboutUs` in a `renderPagina()` function — there is no React Router, no URL changes, no history. The `setPagina` setter is threaded down as a prop into `Navbar` (its `navegar()` handles `Home` / `nosotros`). When adding a new page, follow this same pattern: add a case to the switch and pass `setPagina` down if the page needs to navigate elsewhere.

**The menu / "carta" is a static PDF, not a page.** There is no digital-menu page anymore. Every "see the menu" affordance — the carousel's "Ver la Carta" button (`Carousel.jsx`) and the navbar "MENU" link (`Navbar.jsx`) — calls `abrirCartaPDF()` from `src/constants/carta.js`, which opens `RUTA_CARTA_PDF` in a new tab. It currently points to Hunter's menu PDF on Google Drive (`1NfvrohXV2r_EUp1mX3RLSzp5cF1USX0H`, provided by the client); to use a local PDF instead, put it in `public/carta.pdf` and set `RUTA_CARTA_PDF = '/carta.pdf'`. The old `src/pages/Menu.jsx` / `src/components/SectionsMenu.jsx` were deleted.

**Products API (read-only, currently unused by the UI).** `GET /api/products` (`api/products/index.js`) returns the rows of the Neon `products` table; its schema and seed data are in `scripts/seed-products.mjs`. `src/lib/productosApi.js`'s `obtenerProductos()` is the client wrapper. Nothing renders these anymore — the Home "Productos destacados" grid (`FeaturedProducts.jsx` / `ItemCard.jsx`) and the Clerk-gated admin panel (`src/pages/Admin.jsx`, plus the `POST`/`PATCH`/`DELETE` endpoints, `api/upload.js`, `api/_lib/auth.js`, and `src/constants/categorias.js`) were all removed. The Vercel Function uses the framework-agnostic `export default { fetch(request) { ... } }` Web-standard signature (this is a Vite project, not Next.js). Carousel slides (`DIAPOSITIVAS_BAR` in `Carousel.jsx`) are a hardcoded JS array.

**Env vars this depends on** (see `.env.local`, pulled via `vercel env pull`): `DATABASE_URL` (Neon, pooled — used by `api/_lib/db.js`). The former Clerk (`CLERK_SECRET_KEY`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `VITE_CLERK_PUBLISHABLE_KEY`), `ADMIN_EMAIL`, and Vercel Blob vars are no longer read by any code.

**Styling: Tailwind v4, utility-classes only.** Tailwind is wired via the `@tailwindcss/vite` plugin (see `vite.config.js`), not a PostCSS config. There is no `tailwind.config.js`; the brand tokens are declared in `src/index.css`'s `@theme` block and used as utilities: colors `noche` (black bg), `noche-claro` (cards / alternate sections), `pizarra` (borders), `hueso` (light text, logo), `humo` (muted text), `rosa` / `rosa-oscuro` (flamingo-pink accent, chosen to match the flamingo in the logo; always use `text-noche` on top of it, never `text-hueso`) — e.g. `bg-noche`, `text-rosa`. Fonts: `font-display` (Anton, uppercase headings), `font-etiqueta` (Oswald, small tracked uppercase labels and buttons), `font-sans` (Inter, body); loaded from Google Fonts in `index.html`. Reuse these tokens rather than introducing new hex colors. Custom utilities in `index.css`: `texto-hunter` (white text with black inline, like the logo) and `textura` (grunge noise overlay via `::before`; it sets `position: relative`, so don't put it on `fixed`/`absolute` elements). Recurring patterns: a pink "pastilla" label (`rounded-full bg-rosa text-noche font-etiqueta uppercase px-3.5 py-1`) above a heading whose first line is solid `font-display` and second line is `texto-hunter`; rounded (`rounded-full`) pink buttons and pills, `rounded-3xl` cards, photos and map; photo cards with `<Logo />` centered at the bottom. Brand SVG components: `Logo.jsx` (HUNTER wordmark + flamingo, prop `alto`), `Flamenco.jsx` (paths shared via `flamencoTrazos.jsx`), `Hoja.jsx` (procedurally generated palm frond for low-opacity decorations). Home order: `Carousel` → `SectionPropuesta` (`#carta`) → `SectionUstedes` (`#ustedes`, "Las noches en Hunter": Instagram-like row of 3 photos with the HUNTER mark, linking to their Instagram; the client tried a cocktail-list section here and preferred this) → `FindUsComponent` (`#ubicacion`) → footer. The client asked to remove the Instagram-style highlight circles under the hero and the "Sin reservas" strip above the navbar.

**Animation**: `framer-motion` is used for scroll-triggered and layout animations. `AOS` (Animate On Scroll) is initialized once globally in `App.jsx`'s `useEffect` and its CSS is imported there too — new components can use AOS via `data-aos` attributes without further setup.

**Language**: UI copy, variable names, and comments are in Spanish (e.g. `pagina`, `navegar`, `productoSeleccionado`). Match this convention for consistency when editing existing files.
